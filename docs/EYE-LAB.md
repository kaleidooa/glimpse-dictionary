# Glimpse · 커서 영어 사전 + 시선 추적 실험실

**커서 → Alt + Shift + D → 뜻.** 기본 화면은 웹캠·실험 기록 없이 사용하는 커서 사전입니다. 일반 웹사이트에서는 Chrome 확장으로 사용합니다. **[Chrome 확장 설치·사용 안내](../EXTENSION.md)**를 먼저 확인하세요. v0.3부터 **51,109개 공개 DB 표제어 + 기본 교정 뜻**을 기기 영한 사전으로 제공합니다. 온라인 영영 사전은 선택형 보조 기능입니다. 데이터 출처·활용형 처리·LLM 비교와 측정 결과는 [사전 설계 문서](../DICTIONARY-DESIGN.md)에 있습니다.

기존 웹캠 시선 추적은 별도의 **실험실 BETA**에 보존했습니다. 아래의 시선 보정·학습·평가·기록 설명은 실험실에 해당합니다. 일반 노트북 웹캠의 단어 식별 정확도를 직접 측정하는 연구 도구이며, 단어 수준 정확도를 보장하지 않습니다. 실험실은 기존 기록을 보존하고 새 기본 화면에서는 그 기록을 읽거나 추가하지 않습니다.

## 실행

Node.js 22.12 이상(또는 24 LTS), npm이 필요합니다. 웹캠은 시선 베타를 사용할 때만 필요합니다. 데스크톱 Chrome/Edge를 기준으로 만들었습니다.

```sh
npm install
npm run dev
```

터미널의 주소를 엽니다. 기본값은 **http://127.0.0.1:5173** 입니다. 설치 시 MediaPipe WASM을 복사하고 공식 Face Landmarker 모델(약 3.8 MB)을 `public/`에 내려받습니다. 모델 다운로드에 실패한 경우:

```sh
npm run assets
```

```sh
npm test          # 핵심 알고리즘, 보정 흐름, 사전 fallback 테스트
npm run build    # TypeScript 검사 및 production build
npm run preview  # 빌드 결과 로컬 실행
npm run build:extension # dist-extension에 서버 없는 Chrome 확장 생성
```

## 실험실 BETA 사용

기본 화면의 **실험실 열기**로 들어가세요. 처음에는 마우스 시뮬레이션이 선택되어 있으며, 시선 실험을 하려면 입력 방식을 웹캠으로 바꿉니다. 실험실에는 시선·얼굴 특징·문장·실험 결과가 기기에 저장된다는 안내가 있습니다. 확장에서는 설정의 실험실 버튼으로 별도 탭을 엽니다.

1. 샘플을 읽거나 **텍스트 바꾸기**에서 영어 글을 붙여넣습니다(최대 50,000자).
2. **웹캠 연결**을 누르고 이 로컬 사이트에 카메라 권한을 허용합니다. 마이크 권한은 요청하지 않습니다.
3. 얼굴이 검출되면 **정밀 시선 보정**을 누릅니다. 기본은 25개 위치를 두 번씩 무작위 순서로 보는 정밀 보정(약 2분)입니다. 빠른 9점 보정도 선택할 수 있습니다. 머리와 노트북 위치를 고정하고 눈으로 점을 따라갑니다.
4. 각 점마다 약 750ms 동안 시선을 옮긴 후 1.1초 이상 측정합니다. 유효 샘플 14개 이상이 필요하며, 눈을 찾지 못하면 재시도합니다. 클릭/Space 입력은 필요 없습니다.
5. 보정 후 **학습에 쓰지 않은 무작위 9개 지점**으로 검증합니다(빠른 보정은 5개). 지점별 픽셀 오차와 평균을 표시합니다.
6. 글로 돌아와 단어를 바라보고 잠시 머문 뒤 **Space**를 누릅니다. 선택된 단어 가까이에 뜻이 나타납니다. Escape, 다른 곳 클릭, 스크롤 또는 12초 후에 닫힙니다.
7. **정확도 실험**에서 목적(평가 전용/추가 학습)과 시행 수(50/100/200회)를 선택합니다. 밑줄 표시된 목표 단어를 최소 650ms 바라보고 Space를 누릅니다. 결과를 기록하고 1.3초 뒤 새 목표를 표시합니다. 목표는 화면에 보이는 3자 이상 단어 중 덜 측정한 화면 영역을 우선해 무작위로 배정합니다. 다른 부분으로 스크롤해 표본을 넓힐 수 있습니다. 지정 횟수에 도달하면 자동으로 종료합니다.
8. **JSON / CSV**로 모든 실험 기록을 내려받습니다. `새 실험 시작`은 새 세션을 시작하며 이전 기록은 보존합니다.

카메라를 사용할 수 없으면 **마우스**를 선택하고 단어 위에 커서를 둔 채 약 400ms 기다린 다음 Space를 누릅니다. 마우스 결과는 `source: "mouse"`로 기록하며 웹캠 결과와 합산하지 않습니다. 마우스 모드에서 보이는 정확도는 시선 추정 성능이 아닙니다.

키보드로 입력 필드나 버튼에 포커스한 상태에서는 Space의 기본 동작을 유지합니다. 다시 읽기 영역을 클릭하면 단어 조회를 계속할 수 있습니다. 시선 점 표시는 기본적으로 꺼져 있고 실시간 신호 패널에서 켤 수 있습니다.

## 시선 추정

`React + TypeScript + Vite`에서 `@mediapipe/tasks-vision` Face Landmarker를 사용합니다. 학습된 얼굴 모델을 새로 훈련하지 않습니다.

1. `getUserMedia`로 640×480 영상을 요청합니다. 실제 해상도는 장치가 결정합니다. 동일 프레임은 중복 분석하지 않으며 추론은 약 20Hz로 제한합니다. GPU 초기화 실패 시 CPU로 재시도합니다.
2. 478개 얼굴 랜드마크 중 홍채 중심(468/473), 눈꼬리, 눈꺼풀, 얼굴 위치를 추출합니다. 눈의 로컬 좌표계에서 양쪽 홍채의 가로·세로 위치, 얼굴 x/y, 얼굴 크기, 기하학적 yaw/pitch/roll 대리값을 합쳐 10개 feature를 만듭니다. 포즈 대리값은 물리적으로 보정된 각도가 아닙니다.
3. 눈을 감았거나 눈이 너무 작거나 검출되지 않은 프레임은 제외합니다. 눈의 열림과 blink 점수로 샘플 품질을 계산합니다.
4. 보정 위치에서 feature와 실제 viewport 좌표를 모으고, 지점별 이상치를 제거합니다. **선형 및 홍채 위치의 2차 항을 포함한 ridge regression**을 비교합니다. 정규화 계수 후보는 0.005/0.03/0.15입니다. 절편에는 벌점을 주지 않습니다. 24px 단위의 같은 화면 영역에 속한 모든 프레임을 같은 fold에 묶어 5겹 교차검증하며, 각 fold의 표준화도 학습 부분에서만 계산합니다. 서로 다른 영역이 15개 미만이면 선형 모델만 비교하고, 성능 차이가 5% 이내면 선형 모델을 선택합니다. 최종 독립 검증 점은 이 모델 선택에 사용하지 않습니다.
5. 화면의 RAW 좌표는 보정 전 진단용 휴리스틱입니다. 보정 전 웹캠 좌표로 단어를 조회하지 않습니다. 화면 크기가 바뀌거나 카메라를 재연결하면 다시 보정해야 합니다. 새로고침 후 이전 모델을 자동 재사용하지 않습니다.

## Space → 단어 선택

- viewport 기준 `GazeSample { timestamp, x, y, confidence }`를 최근 1초 버퍼에 유지합니다. timestamp는 `performance.now()`의 단조 증가 시간입니다.
- 트리거 직전 **400ms**만 사용합니다. 최소 4개 샘플, 100ms 이상의 시간 범위, 150ms 이내의 최신 샘플이 필요합니다.
- x/y 중앙값을 기준으로 radial MAD 이상치를 제거한 뒤, 최근 샘플과 품질에 가중치를 주어 fixation center를 계산합니다. 눈 검출 소실·스크롤·리사이즈·숨겨진 탭에서는 과거 샘플을 비웁니다.
- 각 단어는 `data-token-id`를 가진 자연스러운 inline span이며, `getBoundingClientRect()`로 좌표를 측정합니다. 문장 부호와 공백은 원문을 유지합니다. 토큰은 줄 중간에 나뉘지 않습니다.
- box 내부의 단어를 우선하고, 아니면 box까지의 거리를 기준으로 후보 3개를 구합니다. 줄을 잘못 선택하는 것을 줄이려고 세로 거리에 1.8배 가중치를 줍니다. box까지 실제 거리가 90px를 넘는 후보는 제외합니다.
- 선택 신뢰도는 눈 품질·fixation 분산·단어까지의 거리로 만든 **휴리스틱 점수**입니다. 정답 확률이나 MediaPipe의 보증 값이 아닙니다.

## 스크롤 처리

시선 좌표와 단어 box는 모두 **viewport 기준**입니다. 페이지를 스크롤하면 단어 box를 재측정하며, 시선 좌표에 `scrollY`를 더하지 않습니다. 스크롤만으로 화면 gaze 매핑을 재학습할 필요는 없습니다.

- 스크롤 중에는 이전 gaze와 추가 학습용 feature 버퍼를 모두 비우고 팝업을 닫습니다. DOM 측정은 애니메이션 프레임마다 합칩니다.
- 마지막 스크롤 이벤트에서 180ms가 지나야 새 샘플을 받습니다. 그 뒤 새 fixation이 쌓여야 조회할 수 있습니다. 스크롤 도중의 Space는 `scroll-settling`으로 기록하며 오답 trial로 채점하지 않습니다.
- 실험 안내는 스크롤을 따라 화면 위에 유지됩니다. 그 안내에 가려지거나 화면 밖으로 나간 목표는 다시 배정합니다. 새 목표로 시선을 옮기는 650ms 동안의 Space도 채점하지 않습니다.
- 로그에는 scroll x/y, layout revision, 마지막 스크롤 이후 시간이 추가됩니다. 결과에는 **스크롤 후 2초 이내의 정확도**를 따로 표시합니다.

## 오차를 줄이는 반복 절차

**평가 횟수가 늘어나는 것만으로 모델이 개선되지는 않습니다.** 평가 전용에서는 모델을 고정합니다. 실제 정답 위치를 알려 주는 추가 학습과 새 데이터에 대한 평가를 구분해야 합니다.

1. 정밀 보정 후 **평가 전용 50회**로 출발점을 측정합니다. 머리 자세, 화면 배율, 조명을 유지합니다.
2. 목적을 **추가 학습**, 시행 수를 **100회**로 바꿉니다. 현재 읽기 화면의 여러 위치와 여러 스크롤 위치에서 목표를 바라봅니다. 설정 변경은 새 세션을 시작하며 기존 기록은 보존합니다.
3. 추가 학습 모드의 명시적인 목표에 대해서만 눈 feature와 목표 단어 중심 좌표를 저장합니다. 최신 400ms의 유효 프레임 4개 이상, 품질 0.4 이상, fixation 신뢰도 0.35 이상, 흔들림 80px 미만인 trial만 학습에 사용합니다. 마우스 trial·평가 trial·일반 읽기의 예측 단어는 학습하지 않습니다. 사용자가 실제 목표를 바라봤다는 것은 실험 프로토콜의 전제입니다.
4. **학습 반영**은 현재 카메라 보정에 속하는 유효 trial 30회 이상, 서로 다른 15개 화면 영역 이상일 때 가능합니다. 새 모델을 즉시 덮어쓰지 않습니다. 화면 영역 단위로 약 75%를 학습에 쓰고 약 25%를 적용 여부 확인용으로 남깁니다. 확인 영역에 해당하는 원래 보정 rows도 재학습 자료에서 제외합니다.
5. 기존 보정과 추가 학습 데이터로 회귀 모델을 다시 맞추고, 별도로 일정한 좌표 치우침을 보정하는 offset 모델도 만듭니다. 확인용 데이터에서 중앙 오차가 더 작은 후보를 선택합니다. **중앙 오차가 5% 이상 개선되고 P90 오차가 5%를 넘게 악화되지 않을 때만 적용**합니다. 그렇지 않으면 기존 모델을 유지합니다. 이전/새 보정 ID, 확인 표본 수, 전후 오차, 적용 여부를 JSON에 저장합니다.
6. 적용 후 **새 평가 전용 100회**를 수행합니다. 이 새 데이터의 단어 정확도가 최종 확인입니다. 모델 적용 확인에 사용한 수치는 모델 선택용이므로 최종 성능으로 보고하지 않습니다. 같은 확인 세트를 반복해서 고르며 생기는 낙관적 평가도 새 평가로 점검합니다.

P90 오차는 큰 오차가 얼마나 남았는지 보여 줍니다. 정답률의 Wilson 95% 구간은 시행 수가 적을 때의 불확실성을 표시합니다. 이는 독립 trial을 가정하는 근사 구간이며, 같은 사용자의 반복 측정이나 세션 간 변화까지 보장하지 않습니다. 충분한 정밀 보정과 추가 학습에도 오차가 줄지 않으면, 횟수만 늘리지 말고 카메라 배치·조명·얼굴 특징 또는 gaze 추정 방식 자체를 바꿔 비교해야 합니다.

## 실험 지표

같은 철자가 반복되어도 서로 다른 토큰 ID로 채점합니다. 각 트리거 시점의 목표 box와 줄 번호를 함께 저장합니다.

| 지표               | 정의                                                         |
| ------------------ | ------------------------------------------------------------ |
| Exact word / Top-1 | 예측 토큰 ID가 목표와 같은 비율                              |
| ±1 word            | 예측 ID가 목표 ID의 바로 이전·본인·다음인 비율               |
| Top-3              | 목표 ID가 후보 3개 안에 있는 비율                            |
| Correct line       | 예측 단어와 목표 단어의 줄이 같은 비율                       |
| Median error       | 목표 box 중심과 fixation center 사이 Euclidean 거리의 중앙값 |

유효한 목표가 있는 trial에서 시선을 얻지 못하거나 가까운 단어가 없으면 **실패로 분모에 포함**합니다. fixation 자체가 없으면 pixel error는 `null`이며 0으로 취급하지 않습니다. 픽셀 오차를 계산한 trial 수와 미선택 횟수를 따로 표시합니다. 스크롤 안정화, 목표 이동 대기, 다음 목표 준비, 실험 종료 후의 Space와 화면 밖 목표에 대한 입력은 기록하되 새 trial로 채점하지 않습니다.

화면에는 **현재 세션·현재 입력 방식**의 지표를 표시합니다. 새로고침하면 새로운 세션이 시작되며, 이전 기록은 전체 내보내기에 포함됩니다. 개인별 조명·안경·화면 크기·자세를 일정하게 유지하고 50회 이상 측정해 보세요. 같은 단어만 반복하지 말고 여러 줄과 화면 영역을 포함하는 것이 좋습니다.

## 뜻 제공자와 선택적 LLM

`DefinitionProvider.getDefinition(word, sentence)` 인터페이스로 분리했습니다.

- API 키 없이: 기기 영한 DB를 우선 조회합니다. 기본 커서 화면과 Chrome 확장에서 보조 영영 사전을 직접 켠 경우에만 누락 단어를 Free Dictionary API로 보냅니다. 시선 실험실도 같은 기기 DB를 사용합니다.
- 선택적 문맥 해석: **개발용 localhost 시선 실험실에서만** `.env.example`을 `.env.local`로 복사하고 `OPENAI_API_KEY`를 설정한 뒤 개발 서버를 재시작합니다. `OPENAI_MODEL`의 기본값은 `gpt-4.1-mini`이며 계정에서 사용할 모델로 바꿀 수 있습니다. 기기 DB에 없는 단어에 한해 Responses API로 짧은 한국어 뜻을 요청합니다. Chrome 확장은 이 경로를 사용하지 않습니다.
- 키는 Vite 서버 middleware만 읽습니다. **`VITE_` 접두사를 붙이지 마세요.** 브라우저 번들에 키를 넣지 않습니다. `npm run dev`와 `npm run preview`에서 로컬 API를 제공합니다. `dist/`를 일반 정적 서버에 올리면 LLM middleware는 없으며 사전 fallback을 사용합니다.
- LLM 사용 시 선택된 **단어와 해당 문장**만 OpenAI에 전송하며 API 요금이 발생할 수 있습니다. 무료 사전에는 단어만 전송합니다. 카메라 영상·시선·얼굴 feature는 사전 제공자에게 보내지 않습니다.

## 기록과 개인정보

`localStorage`의 `glimpse.experiment.v1`에 모든 읽기 영역 Space 트리거와 완료한 보정 기록을 저장합니다. 타임스탬프, source, 세션/본문/보정 ID, 문맥 문장, 최근 400ms gaze 샘플, fixation, 후보 3개, 선택, 신뢰도, 실패 이유, viewport, trial 정답·오차가 들어갑니다. 보정 기록에는 feature와 목표 좌표, 회귀 계수, 별도 검증 결과가 들어갑니다. 보정 중 취소한 미완성 데이터는 저장하지 않습니다.

영상 자체를 녹화하거나 서버로 업로드하지 않습니다. 카메라 끄기·입력 방식 전환·컴포넌트 정리 시 media track을 중지합니다. 카메라 종료나 모델 로딩 실패는 안내합니다. 저장 공간 오류가 발생하면 메모리에서 계속 측정하고 내보내도록 안내합니다. 원문 일부와 시선 데이터가 포함된 내보내기 파일은 공유 전 확인하세요.

JSON은 보정 원본과 gaze 샘플을 포함하는 전체 자료입니다. CSV는 분석하기 편한 트리거별 행이며, 후보는 JSON 문자열로 포함됩니다. 쉼표·줄바꿈·따옴표와 spreadsheet formula 접두사를 처리하고 UTF-8 BOM을 포함합니다. 서버 DB나 외부 분석 수집은 없습니다. 외부 폰트 요청을 제거했고 시스템 글꼴로 표시합니다. ‘실험 기록 삭제’는 확인 후 해당 출처의 실험 저장소를 비웁니다. 확장 실험실과 localhost 실험실의 저장소는 분리되어 있습니다.

## 알려진 한계

- **실제 사용자의 웹캠 정확도는 아직 측정하지 않았습니다.** 합성 데이터로 회귀·보정 흐름을 검증한 결과와 마우스 모드의 성공률은 웹캠 정확도의 근거가 아닙니다.
- MediaPipe는 화면 gaze를 직접 출력하지 않습니다. 보정 지점에서 학습한 가벼운 매핑은 머리 움직임·카메라 위치·안경 반사·역광·눈의 크기·화면 가장자리에서 큰 오차가 날 수 있습니다. 수십~수백 px 오차가 나면 짧고 촘촘한 단어를 구별하기 어렵습니다. 보정 횟수와 모델 복잡도를 늘려도 정확도 개선은 보장되지 않습니다.
- 카메라 권한은 localhost/HTTPS의 보안 컨텍스트가 필요합니다. 다른 앱의 카메라 점유, OS 권한 제한, iframe 정책도 영향을 줍니다. 연결이 계속 대기하면 주소창의 카메라 허용 상태를 확인하세요.
- 첫 버전은 추론을 UI 스레드에서 실행합니다. 느린 CPU에서는 UI와 샘플링 주기가 지연될 수 있습니다. 여러 얼굴을 동시에 지원하지 않습니다.
- 보정 좌표는 그 시점의 viewport 기준입니다. 화면 크기·브라우저 확대/축소·노트북 각도·앉은 자세가 바뀌면 재보정하세요. 스크롤 후에는 새 fixation이 쌓일 때까지 잠시 기다립니다.
- 단어 토큰화는 영어 알파벳·아포스트로피·하이픈 중심입니다. 모든 언어, 복잡한 약어, 특수 레이아웃을 처리하는 문서 파서는 아닙니다.
- 공개 영한 DB에는 누락·부정확한 뜻이 남아 있을 수 있습니다. 여러 뜻과 출처를 표시하지만 문맥에 맞는 뜻을 자동 판정하지 않습니다. LLM 뜻도 틀릴 수 있습니다.

## 구현 검증

현재 커서 사전의 자동 검사·Chrome 화면 확인·패키지 검사는 [EXTENSION-VALIDATION.md](../EXTENSION-VALIDATION.md)를 참고하세요. 아래는 기존 시선 실험실 검증 기록입니다.

- 자동 테스트 29개: 기존 핵심 테스트와 함께 25점×2 정밀 보정/9점 빠른 보정의 전체 흐름, 스크롤 직후 차단과 새 viewport 좌표 선택, 화면 밖 이동 후 목표 재배정, 50회 자동 종료, 합성 데이터의 비선형 매핑 선택, 알려진 drift 개선, 평가 데이터 학습 제외, 개선 없는 모델의 적용 거부를 검증했습니다. 합성 결과는 실제 사용자 정확도가 아닙니다.
- 브라우저: 마우스 → Space → 한국어 뜻, Escape 닫기, 정답/오답/거리 초과 trial, JSON/CSV 다운로드, 파일 내용, 새로고침 후 기록 유지, 사용자 텍스트 입력과 Space 편집 동작을 확인했습니다.
- 실제 MediaPipe 모델: 공식 공개 샘플 사진에서 얼굴 1개·랜드마크 478개·유효 feature 10개를 확인했습니다. 로컬 웹캠 연결, 얼굴 검출, RAW 좌표 갱신, 보정 화면 진입도 확인했습니다.
- 아직 검증하지 않은 부분: 사용자가 실제로 9점을 바라본 뒤의 단어 정확도, 다양한 카메라/안경/조명, 키를 사용한 유료 LLM 실호출. WebMCP 집계 도구는 지원 실행 컨텍스트가 없어 실호출을 검증하지 않았습니다.
